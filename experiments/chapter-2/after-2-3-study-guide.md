# 第 2 章 2.3 之后：上下文工程记忆型讲义

> 目标：不追求背术语，而是记住每个机制解决什么问题、什么时候会踩坑、如何做工程判断。

## 先记住一张总图

```text
上下文工程 = 放什么 + 放在哪里 + 什么时候更新 + 什么时候删掉

静态、稳定的内容：系统提示词、工具定义、固定示例
动态、易变的内容：时间、状态、进度、当前任务
长期、海量的内容：压缩、检索、子 Agent 隔离
```

**记忆句：固定的放前面，变化的放后面，太多的按需取。**

---

## 1. KV Cache：模型的“读书笔记”

### 它解决什么问题

模型读完一长段上下文后，会为每个 token 计算注意力所需的 Key 和 Value。下一次继续生成时，历史部分不必从头计算，直接复用已保存的 KV，这就是 KV Cache。

### 最容易记住的比喻

第一次读教材，边读边写页边笔记；下一次只看新页并翻旧笔记。若把教材前面某句话改掉，从改动处之后的笔记都可能需要重写。

### 三条工程规则

1. 系统提示词和工具定义一旦确定，就保持字节级稳定。
2. 时间戳、用户余额、任务进度等动态信息追加到末尾，不要改写前缀。
3. 使用标准消息和 chat template，不要把 `system/user/tool` 粗暴拼成普通字符串。

### KV Cache 与 Prompt Cache

- **KV Cache**：一次请求内部，生成下一个 token 时复用历史计算。
- **Prompt Cache**：跨请求复用相同前缀的计算结果。

**记忆句：KV 是“这一趟旅程的笔记”，Prompt Cache 是“下次旅行继续用同一本笔记”。**

### 注意力与 Chat Template

注意力可以记成：

```text
Query：我现在想找什么？
Key：每个词的索引标签是什么？
Value：找到后真正拿走的内容是什么？
```

Chat Template 则像信封格式：API 的结构化消息被转换为模型训练时熟悉的特殊 token。不同模型家族的信封格式不同，因此不要手工伪造角色边界。

### 常见反模式

- 在 system prompt 中写入每秒变化的时间。
- 每次请求都重新排序工具定义。
- 用滑动窗口直接删掉旧消息，连同关键工具结果一起删掉。
- 把 tool result 标成普通 user 消息，破坏多轮思考链。

**检查问题：这段内容会不会改变前缀？会不会让模型失去旧证据？**

## 2. 提示工程：把“聪明”变成“可执行”

系统提示词不是愿望清单，而是员工手册。一个新员工读完后不知道下一步做什么，模型也不会自动补全你的业务规则。

### 五层写法

```text
身份：你是谁
目标：要达成什么
流程：按什么顺序做
规则：哪些情况必须/禁止
输出：最后以什么格式交付
```

### 语气与结构

- 真正关键的约束才用强措辞，全部大写会稀释重点。
- Markdown 负责让人看清层次，XML 标签负责给模型明确语义边界。
- 流程优于一堆散乱规则：验证 → 分类 → 执行 → 校验，比 20 条互不关联的要求更稳。

### Few-shot：什么时候给例子

当输出风格、边界或格式难以用规则描述时，给 2～3 个高质量例子；模型本来就擅长且规则清楚的任务，不要为了“看起来专业”堆例子。

**记忆句：规则说“应该怎样”，例子展示“长什么样”。**

示例也属于前缀的一部分，生产系统应固定示例集，而不是每次动态挑选导致缓存失效。

### 工具定义：给工具写操作手册

一个好的工具 schema 至少说明：用途、参数含义、必填项、边界、示例、与其他工具的关系。工具越多，越需要按需加载完整 schema，而不是一次性把所有工具塞进上下文。

### 提示注入：上下文里的“伪指令”

外部网页、文件、邮件和工具结果都可能包含看似命令的文字。模型看到的是同一个上下文，不能天然区分“开发者规则”和“网页里的指令”。

实用防线：

1. 明确标记不可信数据边界。
2. 把外部文本当作数据，不当作新规则。
3. 工具权限由代码和策略层决定，不交给文本自行升级。
4. 对高风险动作要求独立校验和确认。

**记忆句：输入可以影响判断，但不能改写宪法。**

## 3. Agent Skills：能力的“按需加载”

当系统提示词不断变长，把所有领域知识一次性塞进去会浪费 token，也会让注意力分散。Skills 的核心是渐进式披露：先让模型知道有哪些能力，需要时再加载具体说明。

```text
目录/摘要 → 识别需要的 Skill → 加载完整 Skill → 使用工具完成任务
```

Skill 与工具的区别：

- **Skill** 是“怎么完成一类任务”的流程、知识和约束。
- **Tool** 是“执行一个动作”的接口。

例如“报销 Skill”规定先验票、再分类、再填写；“发票读取工具”只负责读取文件。

**记忆句：Skill 是菜谱，Tool 是锅铲。**

设计 Skill 时写清：触发条件、输入输出、步骤、失败处理、验证方法。Skill 的摘要可放在静态前缀，完整内容按需追加，兼顾可发现性和缓存稳定性。

## 4. Agent 状态栏：给模型一块“仪表盘”

模型不会自动拥有一个可靠的全局任务状态。状态栏把隐式状态显式化，像手机顶部的时间、电量和网络信号。

适合放入：

- 当前任务和子任务进度
- 已完成/待完成步骤
- 当前工作目录或环境摘要
- 工具调用次数、预算、重试次数
- 最近一次验证结果和下一步动作

位置通常靠近上下文末尾，让模型生成当前回答前能看到最新状态。

### 两种实现

- **每轮重建**：状态最新，但若把动态内容插入前缀，会损失缓存。
- **追加事件**：缓存友好，但需要定期压缩旧状态。

**记忆句：状态栏不是日志；日志记录发生过什么，状态栏告诉模型现在该做什么。**

## 5. 上下文压缩：不是“删字”，而是“保留任务所需信息”

上下文变长会带来三种成本：窗口接近上限、注意力被无关内容稀释、每轮 prefill 延迟和费用增加。

### 四种压缩层次

1. **工具输出压缩**：保留结论、关键字段、来源和可回读位置。
2. **消息摘要**：把已经完成的对话阶段压成事实、决策、未决事项。
3. **结构化状态**：把长期有效的信息写成 JSON 卡片或状态对象。
4. **上下文隔离**：把独立子任务交给子 Agent，主 Agent 只接收结果。

### 为什么上下文学习像检索

模型并不是把整段历史平均理解，而是在当前任务下从上下文中“找出有用模式”。因此压缩的关键不是保留最多文字，而是保留能被当前问题检索到的信号：实体、时间、决定、证据、未完成事项。

### 压缩的安全格式

```text
事实：发生了什么
证据：来自哪条消息/工具
决定：已经确定什么
未决：还缺什么
下一步：应该做什么
```

**记忆句：压缩不是把故事讲短，而是把“以后还会用到的线索”留下。**

### 总结与 KV Cache 的关系

压缩能减少上下文长度，但重写前缀可能导致缓存失效。因此生产系统常用分层策略：静态规则保持不变，近期轨迹短期保留，旧轨迹压成稳定摘要，复杂支线交给隔离的子 Agent。
