# 第 3 章：用户记忆与知识库记忆型讲义

> 一句话总览：第二章管理“这一次任务的上下文”，第三章管理“跨任务还能不能想起来的知识”。

## 先建立记忆地图

```text
用户记忆：记住某个人的事实、偏好、经历
共享知识库：记住所有用户都可能需要的文档和规律

写入：提取 → 审核 → 更新
读取：查询 → 检索 → 重排 → 生成
```

**记忆句：记忆系统有两条流水线——写进去要谨慎，找出来要准确。**

---

## 1. 用户记忆：从“记住一句话”到“主动帮助”

### 三层能力标尺

1. **基础回忆**：问到明确事实，能找回来。
2. **多会话检索**：跨多次对话拼出完整背景，能处理同一主题的不同记录。
3. **主动服务**：用户没问，但系统发现多个事实之间有重要关联并主动提醒。

这三层不是“记忆多少”的区别，而是“需要多少关联推理”的区别。

### 记忆的生命周期

```text
当前对话证据
   ↓
提取候选记忆
   ↓
来源/时间/冲突/隐私核验
   ↓
写入或更新
   ↓
按需检索并引用来源
```

**记忆句：模型说过不等于事实，候选记忆必须经过审核。**

### 四种存储形态

| 形态 | 像什么 | 优点 | 风险 |
|---|---|---|---|
| Simple Notes | 便签 | 灵活、易读 | 难检索、易重复 |
| JSON Cards | 档案卡 | 字段清楚、易校验 | schema 设计成本 |
| 可执行状态 | 业务数据库/代码 | 能直接驱动流程 | 权限和错误代价高 |
| 原始对话 | 证据仓库 | 信息最全 | 噪声多、找起来慢 |

最佳实践通常是双层结构：少量核心事实用 JSON Cards 常驻，原始对话按需检索。

### 冲突处理口诀

遇到两个互相矛盾的事实，不要静默覆盖：

```text
谁说的？什么时候说的？证据是什么？是否已确认？
```

保留冲突和时间线，把“最新”与“最可信”分开判断；高风险事实应回问用户或交给审核流程。

### 隐私保护

日志和记忆都要做最小化：脱敏、限制访问、记录来源、支持删除和回滚。记忆系统的目标不是“什么都记”，而是“只记有用且允许保存的东西”。

---

## 2. RAG：让模型在回答前查资料

RAG（Retrieval-Augmented Generation）不是给模型“更多知识”，而是把相关证据在回答前找出来。

```text
文档 → 分块 → 建索引 → 查询 → 召回 → 融合/重排 → 放进上下文 → 生成
```

**记忆句：RAG 的核心不是“生成”，而是先找到对的证据。**

### 文档分块：切得太大和太小都不好

- 太大：检索命中后带来大量噪声，浪费上下文。
- 太小：代词、标题、时间和实体关系被切断。

分块应尽量保持一个完整语义单元，并保留标题、来源、时间等元数据。

### 稠密检索与稀疏检索

- **稠密向量**：按语义相似找“意思接近”的内容，适合换词表达。
- **稀疏/BM25**：按关键词精确匹配，适合订单号、专有名词、代码和数字。

**记忆句：向量懂近义，BM25 认名字。**

### 混合检索与重排序

混合检索先让两种方法各自召回，再融合候选；重排序器对较小候选集做更精细的相关性判断。

```text
召回追求 recall：别漏掉
重排追求 precision：把最相关的放前面
```

## 3. 超越扁平文本：给知识组织结构

### RAPTOR：先概览，再钻细节

把底层文本聚类并逐层摘要，形成树形索引。宽泛问题先命中高层摘要，具体问题再下钻原文。

**像目录和正文：先看目录定位，再翻到具体页。**

### GraphRAG：按关系寻找答案

抽取实体和关系构成图，适合“谁和谁有什么关系”“跨文档关联是什么”这类多跳问题。

**RAPTOR 擅长层次概览，GraphRAG 擅长关系穿线。**

### 文件系统范式

用目录、文件、链接和约定组织知识，优点是可读、可审查、可被工具直接操作；适合持续变化、需要人工协作和明确层级的知识。向量库更适合大规模相似度召回，二者可以组合。

---

## 4. 知识更新：写入不是终点

### 增量更新

新证据到来时，只更新受影响的记忆、索引或摘要，速度快但容易积累重复和冲突。

### 定期整理

回到原始数据，去重、合并、解决冲突、重建索引。成本较高，但能恢复整体一致性。

### 可靠发布流程

```text
Proposer 提议 diff
→ Reviewer 检查证据和冲突
→ 通过后发布
→ 保留版本、来源和回滚点
```

**记忆句：增量更新像打补丁，定期整理像重构；只打补丁，知识库迟早会长歪。**

---

## 5. 智能体化 RAG：让检索会“追问”

传统 RAG 通常“一次查询、一次返回”。智能体化 RAG 把搜索做成工具，让 Agent 能：

1. 判断是否需要检索；
2. 改写查询；
3. 多次搜索不同实体；
4. 发现冲突后继续查；
5. 判断证据是否足够再回答。

它牺牲一些速度，换取复杂、多跳问题的鲁棒性。

用户记忆的典型流程：先搜“车辆保养”，发现有两辆车，再分别搜索每辆车，最后向用户确认指的是哪一辆。只搜一次很容易漏掉另一条会话。

**记忆句：普通 RAG 是图书管理员递一本到书，Agentic RAG 会自己继续查目录、交叉验证和追问。**

---

## 6. 上下文感知检索：给每个分块补“身份证”

孤立分块“该公司第二季度收入增长 3%”缺少公司、年份和章节。索引前先让 LLM 生成短前缀，例如“本段来自 ACME 公司 2025 年 Q2 财务报告的关键指标章节”，再将前缀和原文一起嵌入。

- 对 BM25：增加可精确匹配的实体、日期和章节词。
- 对向量检索：让向量包含原文缺失的语义背景。

要区分两个相似概念：

- 第二章上下文感知**压缩**：运行期，删掉当前任务无关的历史。
- 第三章上下文感知**检索**：索引期，给知识块补上背景。

**记忆句：压缩是在减法，感知检索是在加身份证。**

---

## 7. 从信息检索到知识发现

有些领域的规律不在一篇文档里，而藏在大量案例的统计模式中。做法分两阶段：

```text
非结构化案例 → LLM 提取统一 JSON 因子
             → 数字化编码/聚类/统计分析
             → 因子重要性与典型案例原型
             → Agent 按重要性提问并检索相似案例
```

多分类字段使用 one-hot 开关，例如三种类型用 `[1,0,0]`、`[0,1,0]`、`[0,0,1]`，不要用 1、2、3 让算法误以为类别有大小关系。

**关键转变：知识库不只是“查资料的仓库”，还可以先从数据中提炼决策结构。**

---

## 8. 多模态记忆：文字不是唯一的记忆格式

保存图像、声音等记忆有三条路线：

1. 保存原始文件 + 文本描述：最容易落地，可回看原图。
2. 保存多模态 embedding：检索高效，但需要可靠的向量模型和阈值。
3. 写入支持 Engram 的模型记忆槽：更像模型内部记忆，仍属前沿，需要专门模型。

工程上最稳妥的是第一种和第二种组合：文本做粗检索，原始媒体做最终核验。

**记忆句：描述是目录，embedding 是指纹，原始媒体才是证据。**

---

## 一页复习：六个判断题

1. 用户说过的话是否自动等于长期记忆？——不是，要有来源和核验。
2. 向量检索是否能替代关键词检索？——不能，订单号和专名仍需要稀疏匹配。
3. 分块越小是否越精准？——不一定，可能丢掉上下文。
4. 检索一次是否足够？——简单事实可以，多会话和冲突问题需要多跳检索。
5. 记忆库是否只需要增量更新？——不够，还需要定期整理。
6. 把所有东西转成文本是否保留了全部视觉信息？——不一定，空间关系和细节可能丢失。

## 最终口诀

```text
记忆先审证据，知识再做索引；
向量找意思，关键词找名字；
层次看概览，图谱找关系；
Agent 会追查，分块加背景；
补丁要整理，多模态留原件。
```
